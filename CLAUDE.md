## Commands

### Initial Setup and Development
```bash
# One-command setup (installs deps, builds frontend, runs migrations & seeds)
npm run kickstart

# Run backend and frontend concurrently
npm run dev              # Backend with nodemon on port 3000
npm run dev:frontend     # Frontend on port 5173 (in separate terminal)

# Build for production
npm run build:frontend
npm start               # Starts production server
```

### Database Commands
```bash
# Run from /server directory
npm run migrate                    # Apply migrations
npm run migrate:rollback          # Rollback last migration
npm run migrate:make <name>       # Create new migration
npm run seed                      # Seed database
npm run seed:make <name>          # Create new seed file
```

### Testing and Linting
```bash
# Frontend (from /frontend)
npm run lint

# Backend (from /server)
npm run lint
```

## Architecture Overview

### Tech Stack
- **Frontend**: React + Vite, Three.js for 3D, React Router
- **Backend**: Express.js, PostgreSQL with Knex ORM
- **Auth**: Session-based with express-session, bcrypt
- **AI**: Google Generative AI for challenge generation

### Project Structure
```
frontend/
├── src/
│   ├── adapters/        # API communication layer
│   ├── components/      # Reusable UI components
│   ├── components3D/    # Three.js 3D components
│   ├── contexts/        # React Context (CurrentUserContext)
│   ├── pages/          # Route components
│   └── styles/         # CSS files
server/
├── controllers/        # Request handlers
├── models/            # Database models
├── middleware/        # Express middleware
├── db/
│   ├── migrations/    # Database schema changes
│   └── seeds/        # Initial data
└── scheduler/        # Cron jobs for challenges
```

### Key Patterns

1. **API Communication**: All frontend API calls go through adapters (e.g., `auth-adapter.js`, `post-adapter.js`) which handle fetch requests with credentials included.

2. **Authentication Flow**: 
   - Frontend checks auth via `/api/auth/me` on mount
   - Protected routes use `checkAuthentication` middleware
   - Sessions stored in cookies

3. **Database Models**: Follow Active Record-like pattern with static methods:
   ```javascript
   User.findById(id)
   Post.create(postData)
   Challenge.findByCategory(category)
   ```

4. **Frontend State**: CurrentUserContext provides global user state, consumed via `useContext(CurrentUserContext)`

5. **3D Scene**: ThreeScene.jsx manages the 3D world, with individual components for models (Tree, Bush, etc.)

### Important Routes

**API Endpoints** (all prefixed with `/api`):
- `/auth/register`, `/auth/login`, `/auth/logout`, `/auth/me`
- `/users`, `/users/:id`, `/users/:id/update`
- `/posts`, `/posts/:id`, `/posts/:postId/like`
- `/challenges/category/:category`, `/challenges/complete`, `/challenges/community`

**Frontend Routes**:
- `/` - Landing page
- `/feed` - Main social feed
- `/scene` - 3D interactive world
- `/users/:id` - User profile
- `/community-challenges` - Community challenges

### Database Schema Key Tables
- **users**: id, email, username, password_hash, exp, level, streak, zipcode
- **posts**: id, user_id, challenge_id, content, image_url, likes
- **challenges**: id, title, description, category, points, is_community
- **user_challenges**: Junction table for completed challenges

### Development Notes

1. **Vite Proxy**: Frontend development server proxies `/api` requests to backend port 3000

2. **Environment Variables**: Backend requires `.env` file with:
   ```
   PG_USER, PG_PASS, PG_DB, PG_HOST, PG_PORT
   FRONTEND_ORIGIN (for CORS)
   SESSION_SECRET
   ```

3. **Gamification Logic**:
   - 50 XP for completing challenges (posts)
   - 10 XP for receiving likes
   - Level progression defined in levels table

4. **Challenge System**:
   - Daily challenges auto-generated by scheduler
   - Categories: reduce, reuse, recycle, outdoor
   - Community challenges created by users

5. **File Uploads**: Posts can include images, stored as URLs in database

6. **3D Assets**: Located in `/frontend/public/models/` as .glb files
